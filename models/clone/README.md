# clone — GitHub 참고 모델 실험

**현재 주제: 고장 원인 분류 + 남은 시간(RUL) 예측. 실행 코드와 결과는 [github_rul/](github_rul/README.md)에 있다.**

## 이전 기록: 24시간 조기경보 변형 실험

아래는 앞서 진행한 24시간 조기경보 변형 실험 기록이다. 현재 주제와 구분해 보관한다.

이 폴더는 **clone (원본 참고·변형 실험)** 이다. 원본의 RUL 성능을 그대로 재현했다고 주장하지 않는다.
기존 노트북과 최종 모델은 수정하지 않았다.

## 실행

```powershell
& 'C:/Users/rhkdd/anaconda3/python.exe' -X utf8 -u models/clone/run_clone.py --folds all --epochs 20
```

다른 환경에서는 numpy, pandas, pyarrow, scikit-learn, imbalanced-learn, xgboost,

## 무엇을 가져왔나

| 항목 | 원본 | 이 clone |
|---|---|---|
| 문제 | 고장 원인 3종 분류 + 고장별 RUL | 앞으로 24시간 안 압력 저하 발생 여부 |
| 입력 데이터 | 원시 센서, 140초 집계, M01 10대 | 기존 셔터 1 스텝 구간 요약, 20대 |
| 특징 추출 | 핵심 센서 4개의 이동 통계·추세·파형 계수 | `add_reference_features` 원본 함수를 직접 사용 |
| XGBoost | 깊이 6, 학습률 .1, 150개 + SMOTE | 같은 설정, 이진 분류로 변경 |
| HGBM | 학습률 .05, 250개 RUL 회귀 | 같은 설정, 가중 이진 분류로 변경 |
| GRU | 15행, GRU 64→32, dropout .2, Dense 16 | 구조를 PyTorch로 옮기고 가중 BCE로 변경 |
| 앙상블 | 예측 RUL에 따른 동적 가중 | HGBM·GRU 확률을 사전에 정한 1:1로 평균 |
| 원본의 안전 게이트·원인별 라우팅 | 포함 | 포함하지 않음. 단일 고장의 경보 모델 비교 |
| 입력 구간 초기화 | 미래 TTF 리셋으로 고장 사이클 구분 | 장비만 구분. 정답으로 구간을 나누지 않음 |
| 결측·후처리 | bfill, 사이클 전체 isotonic | 학습 중앙값 대치, 미래를 보는 보정 없음 |

따라서 결과는 **GitHub 구조를 우리 조기경보 문제에 적용한 성능**이다.
원본의 Macro F1 0.965나 RUL MAE 740초와 직접 비교하지 않는다.

## 평가 규칙

- 예측 시각은 **구간 끝**. 그 뒤 86,400초 이내 첫 압력 저하 기록이 있으면 1.
- 학습 앞 60%, 보정 60~75%, 평가 75% 이후 하루를 비운 뒤부터.
- 학습 마지막 하루는 라벨이 보정 기간과 겹치지 않게 제외. 관측 마지막 하루도 제외.
- 모든 모델은 같은 평가 행과 장비-일로 평가.
- 장비-일 = 장비 기록 시작을 기준으로 한 24시간 묶음. 그날 행의 라벨·점수 각각 최댓값.
- 보정 구간에서 정밀도가 양성 비율의 2배/4배 이상인 기준 중 재현율이 가장 높은 기준 선택.
  보정 경보일 10일 이상을 요구. 조건을 만족하지 못하면 경보하지 않음.
- 장비 순환은 고정 난수로 4묶음. 학습·보정은 나머지 15대만 사용, 평가 대상 5대의
  라벨로 임계값·정상 기준·스케일러를 맞추지 않음. 새 장비는 학습 장비의 공정별 기준으로 대체.
- GRU는 학습 장비의 50~60% 구간으로 early stopping. 보정·평가 라벨은 학습에 쓰지 않음.
- 재실행 로지스틱 회귀는 기존 실습 노트북의 13개 특징을 참고:
  압력·유량 z 2개, 이동 평균·변화 8개, 과거 고장 이력 3개.
  과거 고장 로그는 운영 시점에도 알 수 있다고 가정.

## 결과 파일

- `clone_24h.ipynb`: 실제 결과가 포함된 열람용 노트북.
- `results/REPORT.md`: 성능 및 해석.
- `results/summary.csv`: 같은 장비·처음 보는 장비의 합산 성능.
- `results/fold_metrics.csv`: 모델·묶음·임계값별 성능.
- `results/test_day_predictions.csv`: 평가 장비-일별 점수·판정·정답.
- `results/split_boundaries.csv`: 장비별 분할 시각.
- `results/manifest.json`: 환경, 데이터 해시, 입력 특징, 설정, 원본 커밋.
- `results/verification.json`: 저장 가중치 재로딩·예측 일치·임계값·분할·평가일 검증 결과.
- `artifacts/<검증명>/`: 학습 가중치, 전처리기, 임계값, GRU 학습 이력, 보정/평가 예측.

`verify_results.py`는 저장 가중치를 다시 불러와 예측과 지표를 확인한다.
개별 예측 CSV를 직접 읽어 임계값과 비교할 때는 저장 모델의 원래 `float32`/`float64` 형식을
복원해야 한다. CSV에 짧게 표시된 float32 점수를 float64로 해석하면 경계값의 판정이 바뀔 수 있다.

## 해석 범위

기존에 제시한 2,082일·136양성일 실험과 이 실험의 전처리·정상 기준·관측 끝 제외 규칙은
완전히 같다고 확인되지 않았다. **이번에 같은 조건으로 다시 학습한 LR과 clone을 비교**한다.
새 장비 평가도 장비 이력 자체가 없는 cold start가 아니라, 그 시점까지 센서·과거 고장 로그가
있는 장비의 미래 평가이다. 일별 최댓값 지표는 실제 고장 사건별 선행시간·탐지율과 다르다.
여러 모델 중 최고 수치는 탐색 결과이며, 별도 외부 데이터 검증을 대신하지 않는다.
