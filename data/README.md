**익명화**

- 컬럼 이름은 공개돼 있다(예: `FLOWCOOLPRESSURE`). 대회 페이지에 컬럼별 정의가 있다.
- 대회 설명에 "익명화돼 단위를 제공하지 않는다"고 적혀 있다. 확인해 보니 연속형 센서값 16개는 **표준화**돼 있다. 학습 20대를 합치면 평균 약 0(−0.03~0.03), 표준편차 약 1(0.90~1.08)이다. 장비 하나만 보면 평균이 ±0.7까지 벗어나고 거의 변하지 않는 컬럼도 있어, 장비별이 아니라 전체 기준으로 표준화한 것으로 보인다. 실제 단위와 크기는 알 수 없고, 평소 대비 높음/낮음까지만 말할 수 있다.
- `time`은 기준점을 옮긴 정수라 실제 날짜가 없다. 장비·웨이퍼 ID는 코드다.

## 2. 핵심 컬럼 (12개)

**선정 초안** — 예측 대상 고장 3종이 모두 헬륨 냉각 계통이라, 냉각 계통을 직접 재는 센서와 이를 해석하는 데 필요한 운전 조건·정답을 골랐다. 챔버 압력은 대회 설명에 "오링이 냉각 헬륨과 진공 챔버를 분리한다"고 돼 있어, 누설이 챔버 쪽으로 번지는지 보려고 넣었다.

| 컬럼 | 역할 | 설명 | 결측률 |
|---|---|---|---:|
| **`FLOWCOOLPRESSURE`** | 입력 (핵심) | 냉각 회로의 헬륨 압력. 고장 3종(압력 저하·압력 과다·누설)의 이름이 모두 이 값과 관련된다 | 0.0% |
| **`FLOWCOOLFLOWRATE`** | 입력 (핵심) | 냉각 회로의 헬륨 유량(MFC 제어). 압력과 같이 봐야 공급 문제인지 누설인지 구분할 수 있다 | 0.0% |
| `IONGAUGEPRESSURE` | 입력 | 진공 상태인 메인 공정 챔버의 압력 | 0.0% |
| `time` | 시간 | 관측 시각 (초로 추정). 장비 안에서 시계열 정렬·TTF 결합 키 | 0.0% |
| `Tool` | 장비 | 장비 ID. 장비 단위로 나눠 평가할 때 기준 | 0.0% |
| `recipe` | 운전 조건 | 장비 설정 묶음. 레시피마다 정상 범위가 달라 조건별로 비교해야 한다 | 0.0% |

- 고장 직전에 냉각 압력·유량이 실제로 달라지는지는 EDA v2에서 일부만 확인했다(변화 폭이 작음). 다른 센서도 후보로 둔다.

## 4. 주의할 점

- **고장 시각은 정비 시점이다.** 작업자가 장비를 세운 시각이라 실제 이상이 시작된 시점은 더 이를 수 있으며 제공되지 않는다.
- **같은 고장이 반복 기록된다.** 몇 시간 간격으로 같은 고장이 이어지는 경우가 있다(예: `01M02` 압력 저하가 약 2시간 간격). 같은 장비·종류의 기록을 1일 간격으로 묶으면 1,211건이 648건으로 줄어든다. 분석 전에 "고장 1건" 규칙을 정한다.
- **고장이 장비마다 크게 쏠려 있다.** `03M02` 361건, `10M02` 2건. 장비 단위로 나눠 평가하지 않으면 점수가 부풀려진다.
- **누설 고장이 적다.** 137건(중복 제외)으로 종류별 모델을 만들면 누설은 학습이 어렵다.
- **시각 중복이 있다.** 완전 중복 5,470행, 같은 시각에 값이 다른 경우 109,735개. 집계 전에 처리 규칙을 정한다.
- **용량이 크다.** 압축을 풀면 약 35 GB다. 압축 파일을 순차로 읽어 장비별로 1분 단위 등으로 집계한 뒤 쓰는 것을 권한다.
- **실제 단위의 관리 기준은 만들 수 없다.** 값이 표준화돼 있어 장비별 평소 범위 대비 이탈로 경보 기준을 정한다.
- **공정 범위.** 이온 빔 식각은 DRAM·NAND 주력 공정이 아니다. 고장이 난 웨이퍼 뒷면 헬륨 냉각은 메모리 플라즈마 식각 장비에서도 쓰는 구조다.
